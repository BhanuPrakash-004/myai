# AI Personal Knowledge Base — Master Build Prompt

## 1. Project

Build a web application that acts as an **AI-powered personal knowledge base**, replacing traditional manual note-taking.

The system is designed primarily for developers/students who know a topic but repeatedly forget small, important details such as:

* syntax
* APIs/functions
* implementation details
* logic
* common mistakes
* DSA patterns
* LeetCode approaches
* code snippets
* interview-specific knowledge
* important concepts

The user should **not need to decide where or how to save information**. They simply chat with the AI. The AI understands the content, determines whether it is worth remembering, categorizes it, and creates or updates the appropriate knowledge.

### Example

User:

> "I always forget that in BFS I need to take q.size() before the for loop."

AI understands:

```text
DSA → Graph → BFS
Type: Common mistake
Importance: High
```

and stores/updates the BFS knowledge.

Another example:

> "Map.Entry<Integer,Integer> entry : map.entrySet()"

AI understands this belongs to:

```text
Java → Collections → Map → Iteration
```

The user can later ask:

> "What Java Map things do I usually forget?"

or:

> "Explain everything important I have stored about BFS."

or:

> "Quiz me on my Java knowledge."

The application should turn the user's accumulated knowledge into a **personalized learning/revision system**.

---

# 2. Problem

Traditional notes require users to:

1. decide what is important,
2. create a note,
3. choose a folder,
4. categorize it,
5. maintain/update it,
6. remember where they stored it.

Users often don't forget entire topics. They forget **small details inside topics**.

This application solves that by making the AI responsible for:

**understanding → organizing → storing → updating → retrieving → reviewing**

the user's personal knowledge.

---

# 3. Product Goal

Build a system where:

> **The user talks naturally, and the AI maintains their personal knowledge automatically.**

The knowledge belongs to the user and should be stored in **Markdown files**, making it portable and compatible with Obsidian and other Markdown tools.

The application itself provides:

* online access
* AI chat
* knowledge browsing
* intelligent search
* automatic organization
* personalized explanations
* quizzes
* revision
* identification of knowledge gaps and frequently forgotten information

---

# 4. Core Principles

1. **AI-first, not note-editor-first**
2. **Zero-friction capture**
3. **User should not manually categorize knowledge**
4. **Do not save every conversation**
5. **Prefer updating/merging existing knowledge over creating duplicates**
6. **Markdown is the source of knowledge**
7. **SQLite stores application metadata**
8. **User owns/exportable knowledge**
9. **The AI should understand context across the knowledge base**
10. **The system should learn what the individual user frequently forgets**

# 7. Intelligent Memory Capture

Every relevant user message should be classified.

Possible actions:

```text
IGNORE
CREATE
UPDATE
MERGE
DELETE
QUERY
EXPLAIN
QUIZ
REVIEW
```

The AI should determine:

* Is this knowledge?
* Is it worth storing?
* What topic does it belong to?
* Is there an existing related memory?
* Should existing knowledge be updated?
* What importance does it have?
* Is it a syntax, concept, mistake, approach, snippet, API, etc.?

Example structured result:

```json
{
  "action": "UPDATE",
  "topic": "DSA",
  "subcategory": "Graph/BFS",
  "type": "common_mistake",
  "importance": "high",
  "content": "Capture q.size() before processing the current BFS level"
}
```

# 9. Automatic Organization

The user should never need to manually choose folders.

AI determines the best location.

Example:

```text
User:
"Remember Map.Entry is used when I need both key and value."

AI:
Java → Collections → Map
```

If `Map.md` already exists:

**UPDATE IT.**

Do not create another Map note.

If related knowledge exists:

**MERGE IT.**

# 10. Knowledge File Format

Use consistent Markdown.

Example:

````markdown
# BFS

## Core Concept

...

## Important Details

### Queue Size

Remember to capture `q.size()` before processing the level.

```java
int size = q.size();

for (int i = 0; i < size; i++) {
    ...
}
````

## Common Mistakes

* Using dynamic `q.size()` inside the loop.

## Personal Memory

User frequently forgets this detail.

## Related

* DFS
* Graph Traversal
* Level Order Traversal

````

The exact format can evolve, but files must remain readable by humans.
````

# 23. Safety / Data Rules

* Never silently delete knowledge.
* Preserve version/history when updating important knowledge.
* Never overwrite an existing file blindly.
* Never save every conversation automatically.
* User should be able to see what was saved.
* User should be able to correct/move/delete knowledge.
* Keep Markdown exportable.
* Do not send private knowledge to external AI providers when using local AI.
* Clearly distinguish AI-generated knowledge from user-confirmed knowledge.

Do not build all phases at once.

Build and test sequentially.

### MVP stopping point

The first usable MVP is complete when:

```text
User
 ↓
Chat
 ↓
AI understands
 ↓
AI decides whether to remember
 ↓
AI categorizes
 ↓
AI creates/updates/merges Markdown
 ↓
User browses knowledge
 ↓

```

Only after this works should review, quizzes, personalization and LeetCode features be added.

# 27. Product Definition in One Sentence

> **An AI-powered personal knowledge base that automatically captures, organizes, updates, and teaches the small developer-specific things a user tends to forget—from syntax and APIs to DSA logic, LeetCode approaches, code snippets, and interview knowledge.**

# 28. MVP Success Criteria

The MVP should make this interaction feel effortless:

> **User:** "I always forget that BFS needs q.size() before the loop."

> **AI:** Understands it is a personal memory → finds DSA/Graph/BFS → updates the existing knowledge → confirms what was saved.

Later:

> **User:** "What are the coding things I keep forgetting?"

> **AI:** Analyzes the knowledge base and returns the user's most frequently forgotten/high-value items.

That experience—not the Markdown editor, database, or AI framework—is the core product.
